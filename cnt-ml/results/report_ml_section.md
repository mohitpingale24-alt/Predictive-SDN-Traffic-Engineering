# Machine Learning Component: Short-Horizon Link Utilization Forecasting

## 1. Objective

The ML component forecasts link utilization five seconds into the future from recent per-link telemetry. The prediction can support proactive routing decisions when predicted utilization approaches the project's 85% congestion threshold.

## 2. Data Collection and Preprocessing

Phase A generated deterministic synthetic telemetry at one-second intervals for two links, `S1-S2` and `S1-S3`. Each link contains 3,600 seconds of data, for 7,200 raw rows in total. The fields are utilization, throughput, delay, packet loss, queue occupancy, and active flows.

Phase B removed duplicate `(timestamp, link_id)` rows, sorted records per link, repaired timestamp gaps by interpolation, clipped bounded measurements to valid ranges, and ensured that no missing values remained. The current dataset is synthetic and covers one hour per link; it is not a substitute for real Mininet/Ryu telemetry.

## 3. Target Construction

For each link, the target at time $t$ is utilization at $t+5$ seconds. With one-second sampling, this is a five-row forward shift. Rows without sufficient history or a future target were removed, leaving 7,170 feature rows.

## 4. Feature Engineering

The tabular models use 14 features:

| Category | Features |
| --- | --- |
| Current state | utilization, throughput, delay, packet_loss, queue_occupancy, active_flows |
| Lagged utilization | util_lag_1, util_lag_2, util_lag_3, util_lag_5, util_lag_10 |
| Trend | util_ma_5s, util_ma_10s, util_slope |

The planned GRU representation uses raw per-timestamp telemetry over a ten-timestamp window, without the engineered lag and moving-average columns.

## 5. Train/Validation/Test Split

The data was split chronologically with no shuffling. Complete timestamps were kept together across links to prevent one link from being separated from its same-time observations. The resulting split sizes are 5,018 training rows, 1,076 validation rows, and 1,076 test rows.

## 6. Models Evaluated

- **Persistence:** predicts future utilization as the current utilization.
- **Linear Regression:** tests whether a simple linear model benefits from the engineered features.
- **XGBoost:** gradient-boosted trees trained on the 14 tabular features.
- **GRU:** planned sequential comparison model; not trained in the current Python environment.

## 7. Evaluation Metrics

Models were evaluated using mean absolute error (MAE), root mean squared error (RMSE), R², and per-sample inference time. Accuracy and inference cost are both relevant because predictions may be called inside a live controller loop.

## 8. Results

Values below are from `results/metrics_comparison.csv` generated by the current synthetic-data run.

| Model | MAE (%) | RMSE (%) | R² | Inference time (ms) |
| --- | ---: | ---: | ---: | ---: |
| Persistence | 2.2434 | 3.4563 | 0.8193 | 0.0000005 |
| Linear Regression | 2.2537 | 3.2272 | 0.8425 | 0.0007 |
| XGBoost | 2.7820 | 4.0715 | 0.7493 | 0.0027 |
| GRU | Pending | Pending | Pending | Pending |

The GRU row is pending because TensorFlow is not available for the installed Python 3.14 environment. Training requires Python 3.11 or 3.12, followed by TensorFlow installation and a successful run of `src/train_gru.py`.

Persistence has the lowest MAE on this test set and is therefore the current operational model in `src/predict.py`. Linear Regression has better RMSE and R² but slightly worse MAE. XGBoost is slower and performs worse on all three overall accuracy measures in this run.

## 10. Discussion

Persistence is the best current choice for this synthetic test set because it has the lowest MAE and negligible inference overhead. The test set contains no samples at or above 85% utilization, so the evaluation cannot establish which model is safest in the congestion regime. Real Mininet/Ryu telemetry with sustained high-load events is required before changing the deployed model to Linear Regression or XGBoost.

## 11. Limitations

- The dataset is synthetic and may not represent real controller, switch, queue, or traffic behavior.
- The test set contains zero samples at or above the 85% congestion threshold.
- The experiment covers one hour and two links only.
- Overall prediction metrics do not prove that routing decisions reduce congestion, delay, packet loss, or flow completion time.
- GRU accuracy and latency are not yet available because TensorFlow requires a compatible Python environment.
- The selected model should be re-evaluated after real telemetry is collected and the B-H pipeline is rerun.
